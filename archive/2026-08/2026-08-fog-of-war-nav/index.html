GRL-SNAM · incomplete information · vehicle dynamics

Navigating on a map that is wrong.

A vehicle plans against what it believes, not against ground truth — and the two are allowed to disagree. It detours around a building that was demolished, discovers a wall that appeared after the map was made, and routes around a moving unit whose track expires instead of scarring the map forever. It drives with real acceleration and a turning radius, so a late discovery costs it a manoeuvre, not a teleport. Every run below reaches its goal with zero collisions against ground truth.

Belief ≠ truth · sensor-driven · turning radius

02The stale map — a wall the world no longer has

The prior map carries a wall straight across the route. Reality is an open field, but belief is all the agent has, so it commits to the detour and drives it — 37.8 m off the straight line, earned entirely by a building that is not there. Then a ray finally crosses the spot, the ghost clears, and the route snaps straight to the goal. The yellow track keeps the receipt: you can see exactly what the stale map cost.

Note what does not clear — the part of the wall the sensor never swept stays in the map. The agent only knows what it has looked at, which is the honest behaviour and the reason the clearing looks ragged rather than instant.

03The new blocker — discovered on approach

Now the map is right and reality changes: a wall appears across the route after the drive has begun. The agent cannot know until it looks, so this is a genuine late discovery — and it is where the vehicle model earns its place. A point mass would simply reverse its velocity vector. A vehicle with a turning radius has to commit to an arc, which is why the yellow track curves out and around rather than folding back on itself.

The score that matters here is penetration against truth, not against belief — hitting a wall you did not know about still counts as hitting a wall. It stayed out of it entirely.

04The moving unit — a mark that expires

A unit crosses the route. It is marked and avoided like any obstacle, but it lives in a separate layer with a time-to-live rather than in the static map. That distinction is the whole point: baked into belief, a moving obstacle leaves a permanent smear of ghosts along its path, and every future route detours around a corridor nothing is in. 05How it works — two grids, one sensor

There are two maps and they are never the same object. Truth is what is actually there; the simulator senses and collides against it, and it is the only thing the score is computed from. Belief is what the agent thinks — a probabilistic occupancy grid the planner and the obstacle field are built from. The only channel between them is a ray-cast sensor with occlusion: you cannot see through a building, so the gap behind one stays unknown.

Unknown space is a declared policy, not an accident. These runs are optimistic — drive into the unknown and replan on discovery, which is what most real robots do. The pessimistic setting treats unknown as wall and never outruns the sensor; flipping it is a one-word change and a good demo in its own right.

The rebuild is the replan

When the sensor changes the agent's mind, the obstacle field is rebuilt and the route is replanned in the same step. There is no separate "notice the change" pass to fall out of sync.

A turning radius changes the answer

Discovering an obstacle late is only interesting if reacting to it costs something. With a steering limit and a braking model, the recovery is a manoeuvre the vehicle has to fit — which is what makes the margin real.

06Measured once, replayed everywhere

The simulation runs exactly once and writes a trace: one row per world tick — pose, heading, speed, clearance, which map version was current — plus the belief snapshots and the route at every replan. The video, the live window and every number on this page replay that trace and recompute nothing.

That is a correctness property, not bookkeeping. The previous renderer re-derived heading from frame-to-frame motion and overwrote measured speed with playback speed, so the film quietly disagreed with the simulation it claimed to show. Replay removes the possibility. Time is a fixed quantum shared by the simulator and both renderers, so a run is reproducible on a fast machine and a slow one — the same property that makes a benchmark comparable to itself.

07Run it yourself

No world model or trained checkpoint is needed — these three stories define their own world. The package carries the CLI and its whole compiled closure (pycvc_gl, VTK, libcvc), so there is no checkout to make and nothing to pip-install; the prefix activates like a venv.

cvcpkg install cvc/grl-snam-cp311 --prefix ./deps
source ./deps/bin/activate

# 1 · the whole reel in ONE command: record all three, render, concatenate
grl-snam fog all -o fog/            # → fog/fog_demo.mp4 (+ per-story mp4s and traces)

# …or one story at a time (the trace is reusable — record once, replay often)
grl-snam fog list                   # the stories, and any recorded summary
grl-snam fog record ghost           # → traces/ghost/{trace.npz,trace.json}
grl-snam fog capture ghost -o ghost.mp4 --speed 0.5
grl-snam fog play    ghost --speed 0.5 --loop   # same scene, in a window

record is the only step that simulates; capture and play are the same scene builder over the same trace, so the window and the film cannot drift apart. The measured summary in trace.json is where the numbers on this page come from.

Open stack: cvcpkg · libcvc / cvcGL · pycvc / pycvc_gl · VolRover3 · GRL-SNAM. Belief: log-odds occupancy, ray-cast sensor with occlusion. Route: A* over belief. Vehicle: kinematic bicycle. Rendered offscreen through cvcGL's scene renderer — the same engine and the same scene the live window uses.
