GRL-SNAM · VolRover3 · learned navigation

The vehicle finds its own way.

A learned GRL-SNAM policy drives across real Austin, Texas, reacting to the actual buildings through a signed-distance field — with no precomputed route. It even re-targets live: the goal changes mid-drive and the policy redirects on the fly. Trained on the city geometry itself, self-supervised, on a laptop CPU; the films below are captured in 3-D through the same VTK engine VolRover3 uses.

End-to-end · no A* route · dynamic goals

01Start here — one clean run, A → B

A quick orientation before the long drive: the same learned policy on a single fixed start and goal — a ~550 m run threading the Austin street grid, zero building penetration, driven every step by the network. Short and fast; it just works.

02The long drive — the goal changes live

Now the goal is re-targeted mid-drive through four points toward the corners (each a coloured spire — the active one glows). The learned policy heads for whatever goal is current and reaches each one in turn before the next appears; when a potential-field dead-end shows up it follows the wall until it rounds the obstacle. A drone chase cam tracks the vehicle, which paces itself with realistic acceleration and deceleration into each turn. A live HUD overlays the network's own outputs every frame — its predicted coefficients (α, β, γ), wall clearance, drive mode, and building penetration — so you can watch the policy think while it drives. ~3 minutes; the goal switches roughly every 45 seconds. This is exactly what grl-snam pipeline produces from the world model.

03Run it yourself

Everything here is reproducible from the public GRL-SNAM repo through one command-line tool, grl-snam (running against the CVC Python bindings pycvc / pycvc_gl from the CVC stack / cvcpkg). One command takes you from a raw world model — a folder with terrain.json + buildings.glb — all the way to a rendered demo. Full reference: the repo README.md and docs/training-navigation-on-geometry.md.

cvcpkg install cvc/grl-snam-cp311 --prefix ./deps
source ./deps/bin/activate

# 1 · the WHOLE demo in ONE command: world model → SDF → train → HUD video
grl-snam pipeline /path/to/scene_bundle       # → nav_sdf.npz, coef_sdf.pt, mp4

# …or step by step (each artifact is reusable):
grl-snam build-sdf /path/to/scene_bundle                          # → nav_sdf.npz
grl-snam train     /path/to/scene_bundle/nav_sdf.npz -o coef_sdf.pt --steps 1500
grl-snam capture multigoal /path/to/scene_bundle coef_sdf.pt --minutes 3 -o drive.mp4

# 2 · drive it LIVE in VolRover3 (publishes the metrics HUD to the 3-D scene)
grl-snam demo austin-freedrive --bundle /path/to/scene_bundle --checkpoint coef_sdf.pt
#   (or in the app: Jobs tab → Load Script → the grl_snam.demos module → Run as Job)

A scene bundle is a folder with terrain.json + buildings.glb (e.g. an OSM+SRTM export). The long drive on this page is exactly what grl-snam pipeline produces — SDF, training, and the HUD video, from nothing but the world model.

04VolRover3 as an open GRL-SNAM laboratory

These drives are open research, on a stack that is open all the way down — the CVC dependency system, the C++ core, the Python bindings, and VolRover3. GRL-SNAM is the navigation lab on top. Because every seam is a clean public interface, proprietary programs build on the same bench without forking it — adding their sensitive models above the line, in private repositories, while reusing the whole open base unchanged.

The lab is open

Build the SDF, train the navigator, and run these drives from public repos — the field builder even offers CVC's own mesh-exact cvc::sdf, a bridge to full 3-D later.

The program is private

DBG layers its restricted, radio-aware models onto the same navigator through the same bindings — warm-started from the open policy, versioned entirely in its own repositories. The open base never sees them.
